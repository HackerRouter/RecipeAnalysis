# ADR 0015：版本数据由 `oa guide` 现场生成，不入库

- 状态：已采纳
- 日期：2026-11-01
- 相关：`src/oa/report/guide.py`、`src/oa/cli.py` 的 `cmd_guide` 与 `_profile_payload`、
  `docs/shapes.md`

## 背景

适配一个版本需要两类知识：这一版的输入里哪些位置有数据、各自什么形状；以及凭什么这样认、认错会怎样。第一类会随输入变化，第二类不会。

两类内容写在同一个文件里时，第一类会腐蚀第二类：数字过期后整份文件的可信度下降，而读者无法分辨哪些句子仍然成立。

## 决定

两类内容分开存放：

| 内容 | 落点 | 是否入库 |
|---|---|---|
| 某版本的实测结论（目录归属、形状、文件数、未归属项、族级不可用） | `oa guide --label <label>` → `output/<label>/guide.md` | 否 |
| 识别判据（找哪里、按什么形状、什么情况不能认） | `docs/shapes.md` | 是 |

指南的内容全部来自 `oa probe` 与 `oa run` 已有的产物，新增的只是渲染，不新增探测逻辑。手写的版本文件不在必需品之列。

## 换一种做法会错在哪

- **手写版本文件**：数字靠人工抄写与人工更新，没有机制能发现过期。实测中一份千行的版本文件里，绝大多数计数可以原样从产物读到，且存在与产物不符的项——其中有的甚至无法判断是文档写错还是统计口径不同，因为文档没有给出该数字对应的命令。错误不可检出，比错误本身更严重。
- **只写判据，不提供任何版本视图**：判据是跨版本的，读它无法回答「这一版我手上的目录叫什么」。适配者仍需手工跑一遍探测并自己整理，成本从「读一份可能过期的文件」变成「每次重做一遍」。
- **让 `oa guide` 复述判据**：判据会因此在两处存在，改一处忘一处。指南只给结论与指向，判据只有一份。

## 判据

- 仓库内文档不写随输入变化的数字（文件数、可达率、耗时、规模）。需要时现场取。
- 判据文档按「位置 / 判据 / 边界」组织，不按版本分节。
- 指南每节末尾指向判据文档的对应小节；判据文档不复制指南的结论。
- 指南内的路径若要写入产物，仓库内路径转相对并标记仓库根，仓库外路径只保留最后一级——上游目录名属于使用方的机器信息，与复算无关。

## 后果

- `profile.json` 的 `reports` 一节必须同时承载探测布局结论与 provenance。两者共存一个键时若整节覆盖，`components_layout` / `datapack_capability` / `block_report` 会从产物中消失，指南读不到。
- 新增一个版本的流程：放输入包 → `oa probe` → `oa guide` → 按指南与判据接适配器。没有「先抄一份基线」这一步。
- 事实与规则的具体数值以 `output/<label>/` 为准，讨论与验收引用产物而非文档。
