# ADR 0020：关系图的内部表示与可视化分离

- 状态：已采纳
- 日期：2026-11-03
- 相关：`src/ra/report/paths/`、`src/ra/cli.py`（`ra graph`）、
  `src/ra/report/paths/cli.py`（`ra-paths`）

## 背景

来源路径可视化最初是一个 gitignored 的一次性脚本，每次运行都从
`output/<label>/facts/` 重建事实库、编译规则、重算不动点，再渲染图。

这套流程有两个问题：

1. **内部表示没有产物**。规则图只存在于内存里，外部消费者（另一个工具、
   跨版本对比、非 Python 环境）拿不到它。
2. **建图与画图耦合**。调一次画图参数就重算一遍规则与求解，且将来若要缓存，
   必须自己解决失效判断——而这件事很容易做错：一份过期的图看起来和新的没区别。

## 决定

**两条命令分属两个入口，中间是一份文件。**

```bash
ra graph --label 26.3                                    # 产物：output/26.3/graph.json
ra-paths --graph output/26.3/graph.json <物品 id>         # 视图：.dot / .svg / .html
```

`ra graph` 留在 `ra` 下，因为它是管道产物（与 `ra run` 同级，同源同读入）。
`ra-paths` 是**独立命令**，理由两条：

1. **职责不同**。主管道每一步都是下一个的输入；可视化是产物的消费者，
   不产出任何下游要用的东西。
2. **依赖不同**。主管道不需要 Graphviz。独立之后，缺 `dot` 的人仍能跑完
   整条分析链，只在真要看图时才会收到安装提示。

`ra-paths` 只读内部表示文件，不碰 `inputs/`、不重算规则与不动点。

### 内部表示存什么

| 内容 | 为什么必须在文件里 |
|---|---|
| 规则（id / head / body / soft / kind / family / meta / prov） | 图就是它 |
| 三值状态（`true` 与 `unknown` 节点） | 判「这条规则画不画」靠它。只存规则的话，读回的人要么重新求解，要么瞎猜 |
| 种子 | 复算与追溯播种节点 |
| `facts_digest` / `ir_schema` / `graph_schema` | 产物可复算的凭据（AGENTS.md 红线 4） |

缺席的节点按 `FALSE` 处理——这与 `SolveResult.of` 的语义一致，不是省略。

### 格式：单 JSON + 字符串表

| 方案 | 26.3 体积 | 取舍 |
|---|---|---|
| 字段原样 JSONL | 5.5 MB | 可读，但同一个 serializer 名重复上千次 |
| **字符串表 + 下标（采用）** | **2.8 MB** | 体积减半，行序确定，仍可读可 diff |
| SQLite | ~2 MB | 随机访问好，但二进制，不可 diff |
| msgpack / parquet | ~1 MB | 更快，但不可读、不可 diff，且需装包 |

写的 `newline="\n"` 与固定的字段顺序让同一输入逐字节稳定，产物可以直接 diff。

**实测（26.3，2.83 MB）**：读文本 0.009 s，`json.loads` 0.155 s，完整读回到
`RuleSet` **0.16 s**，峰值内存 16.6 MB（文件的 5.9 倍）。而从 `facts/` 重建
规则 + 求解是 0.37 s，所以落盘 JSON 读回反而快 2.3 倍。

JSON 的短板不是速度而是**不能随机访问**：取一个物品的路线要先把全部规则解析
成对象。按当前规则密度外推，500 MB ≈ 145 万条规则，是现在的 90 倍。
真的涨到那个量级时，`store.py` 的 `GRAPH_SCHEMA` 就是升级开关：换格式要 +1，
`read_graph` 直接报错，不会静默读错。

### 不导出 PNG

SVG 已覆盖全部用途（矢量、可拖、可打印）。位图是体积远大于它的额外副本：
2000 节点的图 PNG 是 75 MB，SVG 是 6 MB。旧产物已清理。

### 参数写进文字区，不写进图

同一份内部表示可以用不同参数反复画，所以「同一张图」不是一个稳定的对象：
`130 节点` 与 `175 节点` 可以是同一份数据的两种视图。图被单独传阅时（截图、
隔天打开、发给不跑命令的人），命令行不在了，读者无从判断差异来自参数还是
来自数据变化。

因此生成参数写在 HTML 的文字区（`PathOptions.describe()`），三条规定：

| 规定 | 换一种做法会错在哪 |
|---|---|
| 只写文字区，不进图内标题 | 图内标题会随图缩放，而它恰恰是最需要看清的部分 |
| 写原始命令形式（`--expand-tags True`） | 译成中文就得维护一份只存在于展示层的词表，查不到定义；原文永远与 `build_parser` 一致 |
| 全量列出，不筛默认 | 图脱离命令行后，无从知道某个值是默认还是特意调的 |

反方向的做法是把参数塞进文件名。一旦参数多于两个就没有可读性，且改名会
破坏「同一输入产出同名文件」这个前提。

### 目标物品高亮

一张图讲一件事：这个物品从哪来。满屏矩形里必须能一眼认出「这个」是哪个，否则
读者得先找标签文字。

三重标记同时上：琥珀填充 + 双层边框（`peripheries=2`）+ 加粗字号。只用颜色不行
——色觉差异与黑白打印都区分不出来；只用形状也不行，方框套方框在 200 个节点里
不够显眼。

| 做法 | 错在哪 |
|---|---|
| 只换填充色 | 黑白打印与色觉差异下失效 |
| 用形状区分（如菱形/圆角矩形） | 形状在这张图里已经有语义（菱形=规则、folder=聚合），占用它就没法表达结构 |
| 加一行「目标」文字 | 位置已经说明了这件事（它永远在最上游），重复一遍只占版面 |
| 把目标色放进 `FILL` | `FILL` 按节点排序取值，而目标是一个**角色**：同一个 `item:` 节点既可能是目标也可能只是中间原料 |

目标记在 `PathGraph.target` 而不是渲染参数上：图的主题是图的一部分，`build_dot`
与 `render_html` 读同一处，不会出现标题写 A、图上高亮 B。

### 全局起点不单独画

`world` / `assume` 是分析起点，不是来源。把它们画成椭圆，等于从一个点向几十个
节点射出星形——既占版面，又读不出「这个方块是怎么来的」。

所以它们的边收进产物节点标签的第二行（`草方块 / 结构放置·废弃营地 · 主世界生成`），
反方向则不可接受：

| 做法 | 错在哪 |
|---|---|
| 删掉起点边不做事 | 节点看着无源，读者以为它凭空可得；也违背「剪枝必须留痕」 |
| 把所有起点合成一个「世界」节点 | 267 个节点全连向它，图变成两团 |
| 连指向 `rule::` 菱形的一起收 | AND 的一员被拿掉，规则就残了（交易 = 假设 + 付款物） |
| 把结构名加在「生成」上 | 「生成」是世界给的，与结构无关 |

### 战利品表的三条出路

`table:` 是「从哪拿」而不是「怎么来的」，它不携带分支信息。三种情形三种处理：

| 情形 | 处理 | 判据 |
|---|---|---|
| 表归属唯一来源 | 压成 `来源 → 产物` 边 | 只有一条入边 |
| 多张表出同一种产物 | 各成一条边，不合并 | 压出的边以表名区分，否则会互相覆盖 |
| 预算用尽、表的入边没画 | 表名写进产物标签 | 零入边 |

零入边时**不能直接删**：那是「深度截断」，删了就同时丢掉了「这东西来自战利品」
这条事实，而画面上又没有任何痕迹说明它被删了（违背「剪枝必须留痕」）。
所以把表名写进产物标签（`木桶 · abandoned_camp_barrel`）。

指向 `rule::` 菱形时一律保留节点：菱形是 AND 的一员（挖矿 = 表 + 工具），
吸走表名会让规则说不清楚。

## 换一种做法会错在哪

- **可视化直接读 `output/<label>/facts/`**（原先的做法）：调用方必须知道
  「事实 → 规则 → 求解」这条链，还要跟着 `inputs/` 的路径走；而图本身与
  输入包无关，只与规则有关。
- **内部表示不带状态**：`Builder` 判剪枝靠 `SolveResult`。不带状态就得在
  读回时重算，那就等于没拆开——而且读回的人手上没有种子与知识表。
- **用 mtime 或文件摘要做缓存判断**：用户明确排除这条路。落盘 + 显式指定
  文件之后根本不需要缓存：过期就是一份旧文件，读它的人当场看得见
  `facts_digest`。
- **读到不认识的 `graph_schema` 尽力解析**：字段含义变了，半截解析会画出
  不存在的路径。这类错误不会报错，只会让结论看起来合理。

## 后果

| | 26.3 | 1.18.2 |
|---|---|---|
| 规则数 | 15899 | 9409 |
| 节点状态数 | 5125 | 3300 |
| `graph.json` | 2.83 MB | 1.68 MB |

- 一条命令产出内部表示，可视化可以换任意参数反复画，不必重算。
- 主命令不含 Graphviz 依赖，缺 `dot` 不影响分析管道。
- 全量关系图可跨版本 diff：两份 `graph.json` 的规则表直接对比即可看出机制变化。
- `report/` 仍然不读 `inputs/`：写内部表示在 CLI 层编排，建图与渲染都是纯内存函数。
- 聚合逻辑（来源分类、同构识别、成员层上交）放在 `report/paths/` 而非
  `solve/`，判据见 [`docs/development.md`](../development.md) 的分层硬约束。
